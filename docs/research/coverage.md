## New-provider wishlist

| Provider | Priority | Why |
| --- | --- | --- |
| `algolia` (Algolia) | 1 | Search keys range from public search-only to secret admin keys: a ready-made public-versus-secret pair to document. |
| `circleci` (CircleCI) | 1 | CI service whose personal and project tokens are routinely pasted into pipeline configs. |
| `deepseek` (DeepSeek) | 1 | Model API keys, in the same demand class as the other model providers already recorded. |
| `launchdarkly` (LaunchDarkly) | 1 | Feature-flag service with server-side SDK keys, client-side IDs and mobile keys: a public-versus-secret split inside one provider. |
| `mongodb-atlas` (MongoDB Atlas) | 1 | Database service with programmatic API keys and connection strings that embed passwords: a strong connection-URI collision case. |
| `adyen` (Adyen) | 2 | Payments provider with several credential types (API keys, client keys, webhook HMAC keys) that need telling apart. |
| `airtable` (Airtable) | 2 | Widely used personal access tokens, with older API keys still around; both appear in scripts and automation configs. |
| `auth0` (Auth0) | 2 | Identity provider with client secrets and management API tokens, next to public client identifiers. |
| `bitbucket` (Bitbucket) | 2 | Source host with several credential types (repository, workspace, app passwords) that the vendor documents. |
| `cloudinary` (Cloudinary) | 2 | Media credentials are often written as a URL with an embedded secret, a shape the recorded families barely cover. |
| `planetscale` (PlanetScale) | 2 | Database service with service tokens and connection passwords whose documented prefix scheme is worth verifying. |
| `postmark` (Postmark) | 2 | Transactional email with separate server and account tokens; check whether their shape collides with ordinary identifiers. |
| `segment` (Segment) | 2 | Analytics service with write keys that ship in client code and secret access tokens that must not: another public-versus-secret pair. |
| `snowflake` (Snowflake) | 2 | Data platform with programmatic access tokens and key-pair authentication material. |
| `square` (Square) | 2 | Payments provider with access tokens and application secrets, plus documented sandbox values. |
| `asana` (Asana) | 3 | Personal access tokens are common in automation scripts. |
| `brevo` (Brevo) | 3 | Email and marketing API keys, comparable to the mail providers already recorded. |
| `dropbox` (Dropbox) | 3 | Access tokens of different lifetimes, with documented differences between them to check. |
| `figma` (Figma) | 3 | Personal access tokens are common in design-tooling repositories. |
| `pagerduty` (PagerDuty) | 3 | Incident-response API keys and integration keys, which differ in sensitivity. |
| `render` (Render) | 3 | Hosting platform whose API keys appear in deploy scripts. |
| `snyk` (Snyk) | 3 | Security tooling whose API tokens sit in CI configuration; check whether the shape collides with plain identifiers. |
| `upstash` (Upstash) | 3 | Serverless Redis and Kafka with REST tokens used in client code. |
| `zendesk` (Zendesk) | 3 | Support platform with API tokens and OAuth client secrets embedded in integrations. |
