# Batch 2 research, round 2: carriers for ten carrier-unresolved rows

Issue: credential-evidence#235 (follow-up to the [Batch 2 table](batch-2-bounded-carriers.md) and its [Cases](batch-2-cases-a.md)).

This repository is maintained by the Redact Secret project, which also maintains the product, so none of this is independent validation. Each carrier below is what an official provider page states, read raw on 2026-10-05 and recorded as a `provider-documented` claim in the family's draft contract (revision 1, appended in place). No prefix, alphabet or width was added: every page states none. The Cases are `maintainer-only` project-policy decisions recorded on the owner's instruction (2026-10-05, [ADR 0020](../decisions/0020-solo-maintainer-period.md)) by an AI agent, never `reviewed`, queued for retro-review (#154). This file does not edit the Batch 2 table; the new dispositions are stated here.

Reading notes: the Contentful and Salesforce pages answered curl with a bot challenge (HTTP 429 and 403), so they were read in a browser and the passages cited were checked against the rendered text. Every other page was read with `curl -sL`. Example token values printed on the pages are not copied anywhere. Salesforce's quick start page (`quickstart-oauth.html`) and the Meta system users overview page were read but support no claim and are not recorded.

## Fixtures

Synthetic only (`SYNTHETIC-...-never-issued-NNNN` strings, or the base64 of a synthetic `client_id:secret` pair for Basic envelopes), built for these records and not tested against any service. No fixture takes a prefix, a width or a JWT shape from a page. Sets: `records/fixtures/meta-authored.json`, `contentful-authored.json`, `salesforce-authored.json`, `jfrog-authored.json` (new) and `spotify-authored.json` (appended). Each positive Case has three layouts. Basic envelopes are flagged whole (the secret exists only inside the encoded credential).

## Not done, and boundaries kept

- No Meta kind inherits another kind's carrier; the Meta pages state no Authorization header form for any token kind, and none was recorded or fixtured.
- Subtype (connected app versus external client app, Contentful OAuth versus other content management tokens) is not claimed.
- Percent-encoding, the `!` that Salesforce's page mentions inside access tokens, and token widths are not asserted.
- `docs/handoffs/batch-2-bounded-carriers.md` and `.gitguardian.yaml` were not edited. New synthetic credential-shaped fixture sets (`meta-authored`, `contentful-authored`, `salesforce-authored`, `jfrog-authored`) and the appended `spotify-authored` set may need ignored-paths entries in `.gitguardian.yaml` if the maintainer wants parity with the other authored sets.
- Contracts remain `draft` revision 1; claims and open questions were appended, nothing was rewritten.
